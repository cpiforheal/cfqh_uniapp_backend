# Art Design Pro 取舍建议

本项目当前后台定位为“医护自学资源后台”，服务老师/助教维护四模块题库、公开讲解分发和素材元数据。后台目标是内容维护效率，不是展示型管理模板，也不是教育营销系统。

## 结论：不建议整包拉取 `art-design-pro`

不建议将 `art-design-pro` 整包复制到本项目后再删除改造，原因如下：

1. **当前 MVP 已有稳定技术底座**：`admin/` 已基于 Umi Max、Ant Design Pro、Ant Design、ProComponents 搭建，且现有页面已围绕医护四模块题库、视频分发、素材预览收敛。整包替换会冲击已有路由、布局、主题和数据流。
2. **整包模板噪声过高**：`art-design-pro` 通常包含大量示例页、复杂组件演示、图表大屏、动态菜单、国际化、消息中心等能力；这些能力会增加删除成本和认知负担。
3. **不符合当前产品边界**：项目规则明确禁止在 MVP 中引入支付、订单、直播、社区、排行榜、AI 助教、营销活动等非核心能力。整包模板容易把这些非 MVP 模块带入后台菜单或代码结构。
4. **迁移风险大于收益**：当前真正需要的是页面模式和交互模式，例如紧凑表格、抽屉表单、发布确认、复制素材 Key、详情展开，而不是复制完整工程。

## 值得借鉴并按需实现的能力

建议只把 `art-design-pro` 当作交互和页面模式参考，继续在当前 `Ant Design Pro + ProComponents` 内最小化实现：

- **布局壳与主题 token**：参考更成熟的后台间距、字体、表格密度、暗色/亮色 token 组织方式，但不替换现有主题。
- **权限路由与基础登录鉴权**：后续接真实老师账号时，可借鉴登录页、路由守卫、基础权限判断；当前可先保留轻量入口。
- **表格 CRUD 模式**：保留 ProTable 的查询、密度切换、展开详情、行操作和工具栏模式。
- **抽屉/弹窗表单**：继续使用抽屉承载新增/编辑，控制字段密度，减少跳页。
- **分步表单思路**：对批量导入、题目清洗、视频分发可借鉴“步骤提示”，但不引入重型流程引擎。
- **详情页模式**：题目、视频、素材可用展开行或详情抽屉承载长内容，避免首屏表格拥挤。
- **上传列表模式**：后续接对象存储或视频点播时，可借鉴上传队列、状态反馈、失败重试，但当前只登记素材元数据。
- **操作日志/审计**：后续在老师多人协作时可增加轻量操作记录，例如发布、下线、删除、复制素材 Key。
- **异常页和空状态**：可按需补充 403、404、接口失败、空列表说明，提升后台可维护性。

## 当前不建议引入的能力

以下能力当前不服务医护自学辅助 MVP，不建议从 `art-design-pro` 迁入：

- 多语言与国际化模板。
- 复杂动态菜单和复杂角色矩阵。
- 大屏图表、经营分析、复杂统计驾驶舱。
- 支付、订单、优惠券、营销活动、分销、直播、社区、排行榜。
- 消息中心、站内信、复杂通知系统。
- 复杂组件库示例页、低代码配置页、模板市场页。
- 过多 mock 演示页或与题库/公开视频/素材无关的业务模块。
- AI 助教、智能问诊、医疗建议类能力。

## 建议迁移策略

1. **不要整包复制**：不要把 `art-design-pro` 作为新后台骨架拉入本仓库。
2. **先截图/阅读模式，再局部复刻**：每次只选择一个明确模式，例如“列表页工具栏”“抽屉表单”“详情页”“上传列表”。
3. **用当前技术栈重写最小闭环**：所有实现优先落在当前 `admin/` 的 Umi Max、Ant Design Pro、Ant Design、ProComponents 中。
4. **按操作流优先级迁移**：优先服务老师高频路径：新增题目、发布/下线、复制素材 Key、登记视频分发、发布公开视频。
5. **每次迁移后验证构建**：保持 `cd admin && pnpm build` 通过，再进入下一轮页面精修。
6. **保持 MVP 边界**：任何新增能力都必须能回答“是否提升题库、公开视频、素材元数据维护效率”；不能回答则暂缓。

## 近期最适合继续补的轻量能力

- 题目、视频、素材的操作日志占位：记录发布时间、下线时间、操作者。
- 视频素材从素材页跳转到视频分发页时自动带入 `assetKey` 的轻量前端参数传递。
- 题目发布前校验：标题、一级板块、知识点、答案/解析、选择题选项 JSON。
- 视频发布前校验：标题、一级板块、`assetKey`、`videoUrl`、封面地址。
- 素材列表支持按状态和来源快速筛选，并保留空状态说明。
